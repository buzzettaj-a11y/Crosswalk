# M12: Stages 06 to 09

## Goal

Build the bodies of the last four stages inside the M10 frame. They are Process, Fix problems, Results and Download. Process and Download have no board, so this file specifies them in words. After this milestone an operator can run a batch from the five example files to a folder of downloaded files, decide every open question on the way under their own name, and see the same numbers in the ledger, on Results, on the printed page and in the receipt. No screen shows a count from out-of-date state (H13), no reviewer can type a value (H7), and no progress line can hold a client value (H8). A person whose address cannot be placed is still counted, and every screen says so (P-VAL-2).

7 (all), 8.1 to 8.7, 9.1, 9.3, 9.4, 10.4, 11.4 to 11.9, 6.5 (P-VAL-1 to P-VAL-3 as they show on screen), 6.6 (P-GEO-4, 6 and 7 as they show on Process and Download), 6.8 (P-ID-3 with `earlier_batch`, P-ID-6 and P-ID-7), 6.9 (P-PROG-1 as it shows on Results), 12.6 (opening a source file). ## What to build

File layout under `wholecount/ui/stages/`. One folder per stage, each with `body.py` (builds the stage from a `FrameView` and a `SessionBridge`) and small widget files. Shared widgets go in `wholecount/ui/widgets/`.

```
run/        body.py  summary.py  settings.py  panel.py  found.py  confidence.py
review/     body.py  reviewer.py  twostep.py  tabs.py  causes.py  accept.py  fillpreview.py  compare.py  queue.py  record.py  nolonger.py  corrections.py
summary/    body.py  goals.py  pairs.py  joins.py  programs.py  people.py  printable.py
export/     body.py  files.py  columns.py  folder.py  receipt.py
widgets/    bars.py  pagebar.py  tonetag.py  confirm.py
```

### 0. Shared pieces built first
- `widgets/tonetag.py`. `ToneTag(text, tone)` for tags. Tones are `needs_you` (solid blue), `decided` (green tint, a person's decision), `settled` (gray outline, a rule's decision) and `neutral` (outline). `BandWord(text)` draws Certain, Likely or Possible as plain ink text in 800 weight (SPEC 7.4). A band is never a colored tag. The word is always on screen, so color is never the only cue.
- `widgets/bars.py`. `HBar(fraction, tone)` is a 6px bar (line-soft track, fill by tone `ink-2`, `amber-500` or `blue-500`) and `BarRow(label, value, fraction, tone)` is label, bar and right-aligned tabular figure. Fractions are clamped to 0 to 1 and the bar has the accessible name `{label}, {value}`.
- `widgets/pagebar.py`. `PageBar` shows `Prev`, `Page {n} of {m}`, `Next` and a page size select. It fires `page_changed(int)` and never holds row data.
- `widgets/confirm.py`. `confirm(parent, copy_id, params, ok_label, cancel_label) -> bool` is a modal 440px dialog with a title, one paragraph, a primary and a secondary button. Default focus is the cancel button for anything that discards or accepts in bulk. Every use is a copy ID, so the wording lint covers it.
- Every control that changes data registers with `RunHold` (M10). A static test fails if a class under `ui/stages/run`, `review`, `summary` or `export` fires a command and is neither registered nor on the allowlist with a reason. The allowlist for `QLineEdit` is the reviewer name, the typed count, the second reviewer's name, the Set aside Other note and Search. There's no note box on a bulk accept (SPEC 8.7). None of them holds a client value (H7).
- All grids are `GridView` from M11. All long lists (queue, joins, pairs, people) are served a page at a time through `FrameView` page calls such as `queue_page(filters, sort, page, size)`. A widget never holds more than one page of rows.

### 1. Process (`ui/stages/run/`), no board

The prototype's variant B run panel sits at the top of the stage while a run goes. Everything else follows the order below.
1. **Head.** `STAGE 06 OF 09 · RUN`, h2 `Process`, subtitle `Check every row, place the addresses, find copies and count. Everything happens on this computer.` Primary `HeldAction` `Process everything` (`ProcessAll`), which reads `Process again` after a run. Once a run has finished, `Continue to Fix problems` (secondary, never held) sits beside it. Data line (M10).
2. **Held states for Process everything.** The caption names the first reason that applies, in this order. A job is running (`hold.run`). No table is included, `Held until at least one table is included.` A blocker from M02's `process_blocks`, `Held until {field} is matched for {table}.` (only First_Name, Last_Name and a required Client_ID block, never an address field). A Client_ID column of Social Security numbers, `These identifiers look like Social Security numbers. Map a different identifier, or drop this column.` Program proposals unconfirmed, `Held until {n} program groups are confirmed or kept separate.` When nothing has changed since the last good run the button is not held, and the folded line says `Up to date`.
3. **Pre-run summary.** Shown before the first run, and again whenever the last run is out of date. A white card with a 3px ink top rule, kicker `What this run will do`, and exactly four lines. Each is a copy ID with parameters and has a claim test.
   - `Reads {n} tables from {m} files, once. Nothing in them changes.`
   - `Tidies with {k} steps, checks every row, finds copies inside each file, and finds the same person across files. Rows that need a person go to Fix problems.`
   - The backend line, one of four. `Places addresses with Geosupport Desktop Edition.` Or `Places addresses with the reference file you installed. Only exact matches are placed.` Or, in amber-700, `Does not place addresses, because neither Geosupport nor a reference file is installed. Rows are still checked and counted, and every location reads Not mapped.` Or, for example data, `Practice run. Uses the small sample address file, so locations are for practice only.` The name comes from the engine's `backend.describe()`, never a literal (`CL-RUN-BACKEND-01`). The sample reference never appears as the backend of a real batch (P-GEO-4).
   - The map line, from the two Download switches (section 4). Neither on, `Keeps coordinates out of your clean file. Map counts under 11 are left blank.` The variants add `Exact coordinates are on, for internal use.` and `Moved points are on, each moved 150 to 250 feet. Districts come from the true point.` (`CL-RUN-MAPS-01`). Each ends with a quiet `Change` link that opens Download.
4. **Run settings.** A white card, kicker `Run settings`, under the summary. Controls register with `RunHold`, fire `SetRunSetting(name, value)` and mark Process out of date when a finished run used a different value. The audit's run entry records them (M09). There is no privacy offset switch and no seed (the offset is always keyed to this installation, P-GEO-7). There is no setting that sends unplaced rows to review, because an address never affects the count (P-VAL-2).
   - `Geocoder`, read-only. The backend name with a status tag (`READY`, or amber `NOT INSTALLED`), the reference file name and row count when one is in use (never a row), and the note `Geosupport Desktop Edition is checked on this computer. Nothing is sent anywhere.` Two files in the reference folder read `Two files are in the reference folder, so none is used.`
   - `Extra Geosupport fields (optional)`. One 36px checkbox chip per field M05's `GeoOptions` lists (only `Census tract` today), with `{n} selected`. Disabled with `These come from Geosupport Desktop Edition and can be ticked once it is active.` otherwise. A ticked tract adds census tract rows to Map_Counts and a column chip on Download (`SetExtraFields`).
5. **Run panel.** While a job with action `process` runs, `RunPanel` is the first thing under the head. White card, 3px blue-500 top rule, kicker `Running`, and the `StepList` from M10 with the seven steps of SPEC 11.6.2. Above the list: `Step {i} of 7 · {step name}`, the elapsed time (display only, monotonic clock, one decimal), a 4px overall bar (`ProgressModel.overall_fraction()`) and a secondary `Cancel`. `Cancel` calls `bridge.cancel_job()` at once with no confirmation, since it changes nothing. It then reads `Cancelling...` until the job returns, and the panel becomes a gray notice `Cancelled. Nothing was changed.` Each step change goes through `a11y.announce`. The fast path from Add your files opens this same panel.
   - Finished steps show their found message, for example `6,084 passed, 1,232 need a decision, 96 set aside`. Messages are `ProgressMessage` values only. The panel never builds a string from a row value.
   - A failed job turns the panel into an amber-ruled card. `The run stopped while {step name}. Nothing was changed.` and `Error code {E-xxxxxx}` in the tabular face, with `Try again` (blue) and `Copy the error code` (quiet). The exception text is never shown (H8).
6. **After a run.** The panel folds to one 36px line with the ticker's finish text `Last run finished in 30.5 s · 7 steps, nothing written to disk` and a quiet `Show the log` (a table STEP, TOOK, FOUND, durations to tenths). When the run is out of date the line turns amber and reads `Out of date. {what changed}. Process again.` using M08's staleness reason.
7. **What the run found** (`found.py`). A card with a 3px ink top rule.
   - The first equation from `balance_lines` in 20px 800 tabular figures, `{counted} + {not_counted_yet} + {aside} = {received} rows received`, then `The three add up to the rows received.` (`CL-BALANCE-TABLES-01`). Then the second, `{high} + {low} + {not_mapped} = {counted} rows counted`, then `Not mapped rows are counted. They are just not on the map.` (`CL-BALANCE-LOC-01`, P-VAL-2).
   - Three count boxes. `Counted`, `Not counted yet` (blue count) and `Set aside` (gray), each with a one-line meaning and a quiet link to Fix problems on that status.
   - A `Per table` list, collapsed. One row per included table with the mark, file name, the three numbers, mapped and counted-not-mapped, and the total. A row whose sums fail is amber. Then the card says `These numbers do not add up. That is a fault in Wholecount. Nothing was written, and the counts stay hidden.` and later stages are held (C-23, H4).
   - `{a} rows are in tables you left out, {b} are in blocks that are not tables, and {c} are above the headers. They are listed on Add your files and are not counted.` The table rows and these three equal the non-empty rows in the files (SPEC 7.3), and the line says so (`CL-BALANCE-BATCH-01`).
8. **Confidence callout.** `ConfidenceBlock(view, full=True)` in a callout whose 3px top rule is ink for High and amber for Medium and Low. It shows the level word, the reason sentence, and the three measures each with its value and what High needs (a not-available measure says so). The calibration line shows when M10's slot has a value. A blue `Go to Fix problems` button shows when the reason names rows not counted yet, and `Go to Results` when it names open pairs. For Low, the tick row from M10 sits inside, with the same command and state as the ledger.
9. **Held while a run goes.** `Process again`, every setting, the Low tick. `Cancel` and navigation stay live.

Secondary `Apply a corrections file` (item 18). Primary `Finish review` (`HeldAction`). Data line. No ledger stage section.

5. **No longer apply** (SPEC 5.2, 8.3; `nolonger.py`). When M08's list is not empty, an amber callout sits under the header on both steps. Row actions `Decide again` (`ReturnToOpen`) and `Dismiss` (with an audit event), and a quiet `Dismiss all`. Nothing here shows a cell value.

#### Step 1, the causes (board C3)

6. **Three tabs** (`tabs.py`). A segmented control above the list, `Affects the counts ({n})`, `Location ({n})` and `Worth a look ({n})`, with n the rows in each (SPEC 8.1). Affects the counts holds the problems that keep rows out of the count, the same-identifier conflicts and the open copy groups. Its intro line says copy groups are counted and widen the range. The first tab with an open cause is selected on entry. The Location tab opens with `These rows already count. Fixing them improves the map.` (`CL-LOC-COUNTS-01`). A cause sits in the tab its problem kind's flag names (P-VAL-3), as `Cause.tab` says. The cross-file note sits at the foot of the first tab.
7. **Ranked list** (`causes.py`). One column of `CauseCard` widgets from `FrameView.causes`. Open causes first, largest first, then decided and settled causes, largest first, then the note. A white card with a 1px line border and a 3px top rule, blue for open, green for decided, gray for settled. Left, the count (20px 800 tabular). Then the title (13.5px 800), one line of meaning (12.5px muted) and the actions in a wrapping row. A tag at the top right shows `NEEDS YOUR SAY` (solid blue), `DECIDED BY YOU` (green tint) or `SET ASIDE BY RULE` (gray outline). A cause that overlaps another says `covering {rows} rows`, and totals count each row once.
8. **Actions by cause kind** (SPEC 8.1). Every action is a 36px button and fires one command or job. A kind is the engine's `Cause.kind` from M08's REV-2, and the cross-file note's count is M08's `people_in_other_files`.

9. **Look up all {n}** starts the `look_up` job (the Looking up addresses step shows in the ticker). Nothing is dispatched until `Apply` in the fill preview (item 14).
10. **Accept all as they are** (`accept.py`, SPEC 8.7) opens `AcceptDialog`, 560px, not `confirm`. It shows five rows picked by M08's `sample_rows(decision_id, record_keys)`, so the same decision shows the same five. They sit in a small `GridView` (NAME, ID, ADDRESS, PROBLEM, values on screen only). Under it, a number box `Type {n} to confirm` and a `Reason` select from the accept list in `copy/reasons.toml`. There's no note box, and choosing `Other` adds none (SPEC 8.7, M08's `AcceptProof` has no note). A group over 200 rows also shows `This is over 200 rows, so a second person must confirm.` and a `Second reviewer's name` box. The primary `Accept {n}` is held with `Held until you type {n}.`, `Held until you pick a reason.` or `Held until a second reviewer is named.` and fires `AcceptGroup(reason_id, record_keys, proof, second)`. M08's refusal codes (`count_mismatch`, `second_same_person` and the rest) show as plain lines. The default focus is `Cancel`. The typed count, reason and both names go to the audit (M08, M09).
11. **Set all aside** shows a `Reason` select first, with the fixed list from `copy/reasons.toml`: `Not a client`, `Test record`, `Duplicate of another system's record`, `Out of scope for this report` and `Other` (note of up to 120 characters, same warning, internal log only). Then `confirm`, then `SetAsideRows`. There is no other free text, because text can hold a client value (H7, H8).
12. **Send to row by row** fires `SendToRowByRow(reason_id)`, marks the cause decided with `Sent to row by row` and opens step 2 filtered to it. **Preview** opens a drawer with the first 50 rows in a `GridView` and one sentence for each action that applies, such as `If you accept all, counted goes from {a} to {b}.` The numbers are arithmetic on the balance, not a re-run, and the sentence ends `This is a preview. Nothing changes.` (`CL-PREVIEW-ARITH-01`).
13. **Mapping diagnosis.** A callout (blue top rule) with the bold line `This is a matching problem, not a data problem.` and the engine's sentence, such as `City reads from REGION, which is blank on these rows, while BOROUGH is filled on all 1,842. Fixing one dropdown clears all 301.` Its blue button `Match it and process again` fires `SetMapping(table, field, column)` and then `ProcessAll`, in that order. Decisions are re-applied by record key after the run (A-07, SPEC 8.3). The sentence comes from M08's `diagnose_mapping` (a `MappingDiagnosis` on the cause), never a literal column name.
14. **Fill preview** (`fillpreview.py`, drawer 720px). Title `Look up {n} addresses`, subtitle `Review what would be filled in. Nothing changes until you press Apply.` One `GridView` with a filter `Will fill {a}` and `Left alone {b}`. A fill has NAME, ROW, SOURCE, WAS, WILL BECOME, WHY (the derivation in words and the location confidence word, from P-GEO-9). Left alone has NAME, ROW, SOURCE, WHY NOT. Each fill row has a checkbox, on. `Apply {k} fills` (primary, `AcceptFills(cause_id, record_keys)`) and `Cancel` (nothing dispatched). Every filled row is re-checked on its own, and a row the fill does not fix stays open with its reason. The toast reads `{k} filled, {j} still need a look.` Values are screen-only. The audit gets record keys and field names.
15. **Compare** (`compare.py`). `Compare the {g}` opens a full-height panel over the body with `Group {i} of {g}`, `Previous` and `Next`. Each group shows the reason and a table, one row per record, columns ROW, SOURCE and every mapped field with a difference. Differing values are 800 weight in blue-700. Two choices. `These are the same person` with a radio on the record to keep (default the earliest by source letter, table and row), firing `KeepOneInCopyGroup(group_id, record_key)`, which sets the others aside with the reason `Copy of another row`. `These are different people`, firing `MarkNotCopies(group_id)`, which keeps both and never merges them (H5). For `same_id` groups the text adds `One identifier is being used for two different people.` A decided group shows `DECIDED BY YOU` and a quiet `Reopen`. The header counter follows at once.

#### Step 2, row by row (board C4)

16. **Queue.** Built from these parts, all through `queue_page`.
   - **Status tabs** (segmented, 36px, selected tab ink with light text). `Open ({n})`, `Corrected ({n})`, `Approved ({n})`, `Set aside ({n})`, with counts from the balance. The board's `Rejected` tab is dropped (no Reject, Q7) and `Removed` is called `Set aside`. Open holds every row with an open problem, counted or not.
   - **Filters.** `Problem` (counts, `Any problem ({n})`), `Source file`, `Search` (placeholder `name, address, ZIP, identifier`, matched on screen in memory, never saved, logged or sent to a progress line), `Per page` (50, 100, 250), and `Clear filters`. `Showing {m} of {n} rows in the queue, on one page.`
   - **Selection.** A checkbox column and a page checkbox. When the page is selected and more rows match, a blue-100 bar offers `Select all {m} rows matching these filters`. A selection is filters plus exclusions, and the session resolves it to record keys when a command runs (H12). `{n} rows selected` and `Clear selection` sit by the bulk buttons.
   - **Bulk actions**, all 36px. `Approve as entered` (`ApproveRows`, and over 200 rows it first asks for the second reviewer's name, the M08 reading), `Set aside` (reason select as in item 11), `Return to open` (`ReturnToOpen`), and `Keep one of each person in each program` (`KeepOnePerProgram`), which asks first with M08's exact plan, `Keep {k} rows and set {j} aside. The kept row's record key goes on the reason for each.` (C-16). There is no `Set a field on all`, because a reviewer cannot type a value (H7, Q7). Each bulk command is one Undo step.
   - **Grid.** `GridView` with check, NAME, ID, ADDRESS, PROBLEM, COUNTED (Yes or No, as in the review file), LOCATION, SOURCE. Default order is source letter, table, row. LOCATION shows the confidence word and is empty without an address. Arrow keys move, Space ticks, Enter opens the record.
17. **Record panel** (`record.py`). A 55 percent pane under the grid in a vertical splitter, with its own scroll, closed by Escape. In the order of SPEC 8.2.
   - Header `{NAME} · {ID}`, `{file}, row {n}, counted {yes or no}.` and, with more than one problem, the engine's sentence.
   - `What the problem means`, a bold sentence then the explanation, from the problem's copy ID.
   - `Location`, when the row has an address. The confidence word (ink for High, amber otherwise) and the reason, such as `Matched the street but not the house number`.
   - `The row as it arrived`. Label and value pairs for every mapped column, with the failing value in 800 weight.
   - `{n} columns on this row were never matched`, then their names, then `They stay out of every export.` and a quiet `Show them alongside` (kept from the board). Pressed, each unmatched column's value appears beside the matched fields, under `These values stay on this screen. They are in no download and no log.` (`CL-UNMATCHED-SCREEN-01`, H10). Sensitive columns were already dropped at load (P-READ-9), so one appears only if the operator kept it on purpose.
   - `{n} records share the identifier {ID}`, with a small table (ROW, NAME, ADDRESS 1, ZIP). Differing fields are 800 weight in blue-700. `Open row {n}` selects that record.
   - `Suggested: {fill}` in blue-700, the basis sentence, `Apply and check again` (blue, for this record) and `Not this one`. Only a suggestion derived from the row itself is offered. A near match from the fallback reference is shown, never placed (P-GEO-3).
   - Buttons `Approve as entered`, `Set aside` (reason select), and for a decided row `Return to open`. No Reject, no typing.
   - Quiet `Open the source file`. `confirm` asks `Open {file name} in the program Windows uses for it? Wholecount sends nothing. Windows opens the file the way it does when you double-click it.` It calls `ui/shell.py open_source_file(path)`, which takes only a file added to this batch, registers it with M00's `guard.allow_open_file(path)` and then calls `os.startfile`. `ui/shell.py` is the one file the static scan exempts (SPEC 12.6). Off Windows it says `This works on Windows.`
18. **Corrections files** (`corrections.py`, SPEC 8.6). `Apply a corrections file` opens the Windows open dialog (CSV and Excel) and starts the `corrections` job (Reading the corrections file, Checking signatures and originals, Re-applying decisions, SPEC 11.6.2).
