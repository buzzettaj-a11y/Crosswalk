# M11: Stages 01 to 05

## Goal

Build the bodies of the first five stages inside the M10 frame. They are Add your files, Your columns, Tidy up, Match your columns and Programs. Every control fires a session command, every held control says what releases it, every stage has its data line, and every feature in the decisions doc's feature ledger that belongs to these stages has a widget and a test. Drag and drop works (A-18).

## Spec sections

11.4, 11.5, 11.8 (the data lines are M10, mounted here), 4, 5.1, 6.1 (P-READ-2, 5, 6, 7, 8, 9, 10), 6.2 (P-MAP-2, P-MAP-6, P-MAP-7), 6.3, 6.6 (P-GEO-4 and P-GEO-4a, for example data), 6.9, 10.2, 10.3, 12.6. Also H4, H6, H10, H11, H16.

## Depends on

M10 (frame, `StageHead`, `HeldAction`, `DataLine`, `StepList`, callouts, tags, source marks, the ticker, `SessionBridge`). M01 (readers, table detection), M02 (fields, mapping, column check), M03 (tidy-up steps and their dry run counts), M07 (program proposals), M08 (commands, staleness), M09 (saved progress and set-ups).

Command names below are intents. Use the names M08 gave them, and list each difference in the report.

## What to build

### 0. Shared pieces built first

- `ui/widgets/grid.py`. `GridView(QTableView)` over a `QAbstractTableModel`. It keeps its vertical and horizontal scroll offsets and its page across a model reset (`GridState` held by the window, keyed by `(stage_id, grid_id)`), and opening a different stage starts at the top. Header is column-head style on bg-surface, rows 36px, alternating none, 1px line-soft row rules, tabular figures where a column holds numbers. It scrolls on its own and the page never does. Sorting is by a header click through the model. Page size select (50, 100, 250).
- `ui/widgets/preview.py`. `DataPreview(table_key)` shows the first rows of a table through `GridView`, 50 rows a page, with the header row picker above it (the legacy tick list, rebuilt). It opens as a drawer from the right (same `Drawer` as M10, 720px) from every `Show data` button. Picking a row fires `SetHeaderRow(table_key, n)`, with a `none` choice that numbers the columns. When `header_looks_wrong` is true the drawer opens with an amber callout `The header row may be wrong` and the engine's reason. It shows continuation blocks (P-READ-5) with a note.
- `ui/widgets/setups.py`. `SetupsPanel` (SPEC 10.3). Save current set-up as `[name]` with an optional note (`SaveSetup`). A list of saved set-ups with saved time and the file names it was made for, `Check` (builds a fit report against the files loaded now and says what loads and what does not), `Load this set-up` or `Load what fits and skip the rest` (`LoadSetup`), `Delete`, `Export to a file` and `Import from a file` (both through the Windows file dialog). The export is plain JSON, because DPAPI output can't move to another computer (SPEC 10.3, M09 STORE-6), and the export screen says what's in it: column names, steps, mappings, defaults and program names, with no client data. The panel says `No client data is saved in a set-up. Column names are its only link to your data.` It appears here (collapsed card at the bottom of Add your files) and on Download (M12).
- `ui/stages/_common.py`. `card()`, `section_head(number, text, note, action)` (the numbered head from the style guide), `source_label(source)` (mark plus name), `pluralize(copy_id, n)`.

If they do not add up, the card turns amber and says so with the numbers, and Process is held (`Held until every row in every file is accounted for.`).
9. **Saved set-ups** (collapsed `SetupsPanel`).

Behavior.

- Adding files runs the `add_files` job (Reading files, Finding tables). Under 300 ms nothing shows. The list updates once, after the job applies. Adding the same file again (same fingerprint) says `{name} is already added.` and changes nothing.
- **Drag and drop (A-18).** The whole body of this stage accepts drops, and the drop zone shows the target. `dragEnterEvent` accepts only when every dropped item is a local file (`QMimeData.urls()` with `QUrl.toLocalFile()` non-empty and no directory). Over a valid drop the zone shows a 2px blue-500 dashed border, a blue-100 fill and `Drop to add {n} files`. Over an invalid drop it shows an amber border and `Only files on this computer can be added.` and the drop is ignored. `dropEvent` starts the `add_files` job with the paths. Drops anywhere else in the window (other stages, the chrome, text fields) are ignored, and a text field never receives a dropped file path as text. An application-level event filter does this. Paths starting with two backslashes are refused with `Wholecount cannot open files by network address. Map the share to a drive letter, or copy the file to this computer.` A file on a mapped network drive is allowed and shows the amber note from 12.6. Detect it with the kernel32 drive type call. `kernel32` is already on the guard's ctypes allowlist from M00 (`DPAPI_DLL_NAMES`), so no guard change is needed. If detection is not possible, show nothing and log the choice.
- Reading goes through file objects only (P-READ-10). The UI never passes a path string to pandas, openpyxl or lxml, and it never builds a URL.
- Held while a run goes. `Process everything`, `Browse`, `Try example data`, every table tick, the system selects and `Remove file`. The drop zone shows the held caption and ignores drops.
- Strip caption is the M10 one. The ledger This batch section updates. There is no stage section.
