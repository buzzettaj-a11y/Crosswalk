# Crosswalk: technical documentation

_Generated by `tools/make_docs.py` from the source. Do not edit by hand; change the code or the generator and rebuild. `tests/test_docs.py` fails when this file is stale._

## 1. Purpose

Crosswalk exists to answer two questions for a New York City human-services
nonprofit whose clients are recorded in many separate systems (ETO, property
management, DYCD exports, partner spreadsheets), each with its own identifiers,
column names and spellings:

1. **Unique clients across every system**: each person counted once, however
   many files they appear in.
2. **Unique clients per program**: the same person counted once in each
   program they take part in.

To get there, every file is turned into one shape, cleaned, checked, placed on
the map through the city's own address engine, de-duplicated within files, and
resolved across files into one master identity per person. Every change is
recorded by identifier, never by value, so the result can be trusted and
traced without exposing client data.

## 2. Hard rules

These are design constraints, not preferences. Code that violates one is a bug.

- **Offline.** No network calls in the processing path. Geosupport runs locally.
- **Deterministic.** The same input and settings give the same output. No model, no black box. Every rule is written down in this file's reference.
- **Lossless.** clean + review + set aside = input, on every run. Rows are set aside, never deleted.
- **Nothing merged on a guess.** The engine collapses records only where the same identifier appears with identical data. Everything else is proposed to a person, with evidence.
- **Originals preserved.** A tidy-up step adds columns; it never overwrites. The value as entered stays on the row and in the audit.
- **PII-safe audit.** The audit trail and the summary page carry identifiers and column names only.
- **No per-value editing in the app.** The record panel offers only the changes that are safe at scale: fills derived from the row's own address, keeping one of a group of copies, splits. Anything else is fixed at the source and reloaded.
- **Plain words.** Guided mode uses no jargon. Advanced mode uses the precise terms. Only the words differ.

The server is a single process. All state lives in one dictionary, `S`, in
`crosswalk_server.py`; section 5 lists its keys. The interface fetches one
JSON payload per screen (`GET /api/ui?screen=...`) and renders it; every
change is a POST that mutates `S` and, where needed, reprocesses. Reprocessing
runs in a worker thread so the server keeps answering, and reports progress
per file into `S["run"]`, which the page polls to draw the processing card.

### The row's journey through `app.transform_row`

1. Read each mapped column, cleaned (`clean_cell`: placeholders such as NULL emptied, spacing and hidden characters removed).
2. A summary row (a total, a heading, bare numbers) is flagged as exactly that and returned; it joins no other group.
3. Defaults fill blanks: a value set for this source first, then the schema's. Program is a custom field and takes both.
4. Names: a jammed name is split earlier by a tidy-up step; here the middle initial is reduced to one letter; digits in a name are flagged.
5. Address: a unit found at the end of the street is moved to Address 2; a unit in both lines is de-duplicated, or flagged when they disagree.
6. ZIP is reduced to five digits or flagged. City is filled from the ZIP when blank; a recognized borough that contradicts the ZIP is flagged; an unrecognized city with a valid ZIP is replaced by the ZIP's borough, recorded. State is written as NY or flagged.
7. Custom fields are cleaned, typed and validated.
8. A duplicate rule's marks from `dedupe_rules.apply_decisions` are honored: kept rows are marked, set-aside rows are flagged with the row they copy.
9. Every fix, fill and failed check is written to the audit by identifier.

Then, over all rows: Tier 1 duplicates (same identifier, identical data: keep the first, set the rest aside), Tier 2 possible duplicates across files (same person key, shown, never merged), geocoding (Geosupport, else the reference data), districts from true coordinates, jitter applied to stored coordinates only.

### Identity resolution (`identity.py`)

Records are blocked into candidate pairs that agree on two independent facts,
scored on name (with nickname groups and each half of a double surname), date
of birth (with swapped-digit tolerance), address and identifier, and joined
automatically only above a threshold that coincidence cannot reasonably
reach. Pairs between the propose and auto thresholds are shown with evidence.
The person's decisions are replayed on every resolution. Goal 1 is the count
of master identities; Goal 2 the count of distinct (master identity, program)
pairs.

## 5. The working state `S`

Every key of the server's state and what it holds. Saved between sessions by `sessions_store` (decisions and set-up only, never `frames`, `uploads` or `results`).

- `uploads`: the uploaded files as bytes, by file name (for Open the source file)
- `tables`: every table found, with its kind, range and summary
- `frames`: the raw table for each table key, as strings
- `blocks`: the raw grid for tables whose header row can be re-chosen
- `header_row`: which row holds the column names, per table
- `included`: whether each table takes part
- `schema`: the column set-up, or None for the standard set
- `ops`: tidy-up steps, each with its table, origin (auto or manual) and removed flag
- `map_ov`: matching choices a person made, per table, over the tool's proposal
- `confirmed`: tables whose matching a person confirmed
- `source_defaults`: values used where a field is blank, per table
- `settings`: processing settings: require_geocode, jitter, seed
- `gde_fields`: optional Geosupport fields to include in the output
- `results`: the last processing run: transformed, clean, review, audit, quality
- `rid_index`: record id to record, for the review stage
- `actions`: every decision a person took, replayed to give each row its status
- `queue_edits`: corrections applied in review, by record id and field
- `mode`: Guided or Advanced
- `stage`: the stage on screen
- `max_stage`: the furthest stage reached
- `undo`: snapshots of the set-up before each change
- `identity`: the cached identity resolution, or None when stale
- `id_decisions`: confirmed or rejected links between records
- `dup_fields`: which fields make two rows one person within a file
- `dup_decisions`: per table, per group: copies, copies:N, or keep
- `program_groups`: the grouping of program names, and program_aliases the map it produces
- `program_preview`: the last preview of the two counts, and whether it is stale
- `run`: processing status: state, phase, message, progress, file, steps left

## 7. Module reference

Every class and function, with its signature and docstring, read from the source.

### `crosswalk_server.py`

_The web server: every API route, the working state, and the wiring between the engine and the interface._

Crosswalk server: the redesigned UI's backend, wrapping the existing validated
engine in app.py. Runs fully offline on localhost for a single operator.

Every number shown in the UI comes from the real pipeline. Review decisions are
kept as a replayable action log; corrections made in review re-enter the same
pipeline (validation, geocoding, districts) rather than bypassing it, and every
row keeps its lineage. Lossless invariant at export: the clean file plus the
review file always equal the input rows, and the server asserts it.

#### class `_Up`
Adapter so engine readers accept raw uploaded bytes.
- `__init__(self, name, data)`: Creates one, with the values given.
- `getvalue(self)`: The bytes of the uploaded file, as the engine's reader expects.

#### `_blank_state()`
The working state as it is when nothing has been loaded.

#### `_snapshot(label)`
Remember what the state looked like before a change, so it can be taken
back. People only try things when backing out is safe, and every stage
before Review had no way back.

#### `_undo_last()`
Restore the snapshot taken before the last change, and say what it was.

#### `_autosave()`
Write the resumable parts of the state. Never writes uploaded rows. Failure
is not allowed to interrupt the operator's work, so it is reported on the
screen rather than raised.

#### `_fmtn(n)`
A number with thousands separators, for messages.

#### `_load_reference()`
The geocoding reference: Geosupport if it is set up, else the gazetteer and district files, loaded once.

#### `_preflight_summary()`
The system check, run once and cached, with a one-line verdict.

#### `_included_keys()`
The keys of the tables that take part in the run, in order.

#### `_active_ops(table_key=None)`
The tidy-up steps in force for one table, in order, skipping removed ones.

#### `_prep_signature(table_key)`
What a prepared frame depends on: the raw frame, its header row and the
active steps. If none of these changed, neither did the frame.

#### `_prepared(table_key)`
The table with its tidy-up steps applied, built once and reused until
something it depends on changes. One screen asks for this many times
over, and a step such as the calculated ZIP column looks every address up,
so rebuilding it on each call made every click slow. Callers that change
the frame must copy it first.

#### `_forget_prepared(table_key=None)`
Drop cached prepared frames, for one table or all, so they are rebuilt.

#### `_schema()`
The column set-up in force: the person's, or the standard set.

#### `_required_roles(schema)`
The roles a row must have for the schema given.

#### `_guess_for(table_key)`
The matching for one table: the tool's proposal with the person's choices over it, plus the column list.

#### `_match_custom(cols, label)`
Propose a source column for one custom field by its label.

#### `_table_ready(table_key)`
Whether every required field has a column. City and State are filled from
the ZIP, so a file with no column for them is ready as long as it has a
ZIP; the matching stage says exactly that, and this must agree with it.

#### `_samples(df, col, n=3)`
A few distinct values from one column, shortened, for showing under a dropdown.

#### `_rid(rec)`
The stable identifier of a record: its table key and row number.

#### `_classify(rec)`
Put a row in the group that names the CAUSE of its problem, not a symptom.

A blank or unusable ZIP is the common root cause: the city is filled from
the ZIP, so when the ZIP is missing the city cannot be worked out either and
the row reports both. Grouping such a row under the city sends a reviewer to
fix the wrong field. Order below runs from most fundamental to least, and a
row that reports both a ZIP and a city problem is grouped as a ZIP problem.

#### `_group_diagnosis(gid, rows)`
Say what a group's rows have in common that a person can act on.

A field blank on every flagged row from one source is not a data problem
on those rows, it is a matching problem on that source, and the fix is one
dropdown on the Map stage rather than a decision per row. This finds that
case and names the column that looks right.

#### `_calc_note(rec)`
The reason a calculated column left a row blank, read from the prepared
row. A row whose ZIP could not be worked out arrives in review saying why,
which is what a person needs to decide it.

#### `_review_rows()`
The rows in review, grouped by the cause each is classified under.

#### `_split_possible_duplicates(res)`
Possible-duplicate rows split into within-one-file and across-files.

#### `_cross_file_matches()`
What the review stage says about rows matched across files: a count and
an explanation, never a decision to make.

#### `_replay()`
Replay the action log into per-rid and per-group statuses.

#### `_tallies()`
The counts the review stage shows: failed, cleared, queued, undecided, decided.

#### `_collect_corrections_meta_and_patch(prepared_frames)`
Apply uploaded corrections files plus in-review corrections; return meta.

#### `_execute_pipeline()`
Build the prepared frames, apply corrections and duplicate decisions, run the engine with progress, and index the result.

#### `_run_thread()`
Run the pipeline in the background, recording progress and any error in the run status.

#### `_recompute()`

#### `_export_sets()`

### `app.py`

_The engine: reading files, cleaning, splitting, checking, geocoding, de-duplicating, and the exports. Also the original Streamlit interface._

================================================================================
 Crosswalk
================================================================================
A 100% offline, air-gapped Streamlit application that merges messy client data
from several disparate EHR exports (.csv / .xlsx / .json / .xml / .tsv) into a
single clean "standard" dataset, validates every field, geocodes addresses
against a LOCAL reference file (no external APIs), applies a privacy jitter to
the coordinates, and presents a review dashboard before any export.

--------------------------------------------------------------------------------
 PRIVACY / SECURITY MODEL  (read before modifying)
--------------------------------------------------------------------------------
* No outbound HTTP/API calls anywhere in this file. Geocoding is performed by
  matching against a local CSV (`nyc_address_points.csv`). The only disk READ is
  that reference file. Nothing is written to disk: uploads are parsed from RAM
  (BytesIO) and all downloads are streamed from in-memory strings.
* The exported audit log (`Secure_Audit_Log.txt`) references ONLY system IDs.
  It never contains a client name or a full street address. Boroughs and ZIP
  fragments may appear because they are low-sensitivity and needed to explain a
  transformation, but personally-identifying combinations are excluded.

--------------------------------------------------------------------------------
 MASTER SCHEMA (the single target every file is transformed into)
--------------------------------------------------------------------------------
    First_Name      str            required
    Middle_Initial  str, len 1     optional/nullable, uppercased
    Last_Name       str            required
    Client_ID   str/int        required, globally unique across the merge
    Address_1       str            required (may legitimately contain Apt/Suite)
    Address_2       str            optional/nullable
    City            str            required, one of the 5 NYC boroughs
    State           str            must be "NY"
    Zip             str            required, 5 digits

--------------------------------------------------------------------------------
 LOSSLESS GUARANTEE
--------------------------------------------------------------------------------
Every input row ends up in exactly one of two output buckets:
    1. Final_Clean_Mapped.csv     -> validated, geocoded, jittered, perfect
    2. Manual_Review_Needed.csv   -> anything imperfect, with its ORIGINAL data
                                     preserved plus a human-readable reason
No row is ever silently dropped. (clean count + error count == input count).
================================================================================

Universal scalar cleaner applied to every source value before any logic.

#### `_normalize_separators(text)`
Treat a dash, slash, semicolon, colon, pipe or backslash used as a field
separator as if it were a comma, so the parser can find the parts around it.

Only separators surrounded by whitespace are converted. That keeps genuine
address content intact: 40-22 24th St, 123-A, and c/o all lack the spaces,
so they are untouched.

Clean a piece produced by a split: collapse repeated separators, remove any

#### `split_jammed_address(raw)`
Split a jammed single-field address into street / unit / city / state / zip.

Works from the right: it peels a trailing ZIP (or ZIP+4), then a trailing NY
state token, then a city, then a secondary unit (apartment, suite, floor,
room, etc.) which goes into `unit` (Address_2). The remaining primary street
goes into `street`. The city is taken from the segment after the last comma
when commas are present, or matched against the known NYC boroughs and
neighborhoods when there are no commas. Anything it cannot confidently
attribute stays in street, so no data is lost. Any field may be empty.

#### `split_jammed_name(raw)`
Split a jammed single-field name into first / middle initial / last.

Handles the two common forms:
    "Last, First M"   (comma-separated, last name first)
    "First M Last"    (space-separated, natural order)
The middle token is only treated as a middle initial when present; it is
reduced to a single uppercase letter. A trailing generational suffix
(Jr, Sr, II, III, IV) is folded back onto the last name so it is not lost.
Returns a dict with keys first, middle, last (any of which may be "").

#### `normalize_middle_initial(raw)`
Middle initial must be a single uppercase letter (or empty).

Handles: lowercase letters, and the case where a *full* middle name landed in
the column (e.g. "Suzanne") -- we reduce it to its first initial rather than
discarding the row, since the master schema only wants the initial.

* fallback : a ZIP discovered elsewhere (e.g. embedded in a jammed address),
             used only when `primary` is empty.

Returns (zip5, note, error). `error` is a human message if the ZIP is
unusable; otherwise "".

#### `guess_mapping(columns)`

Three rules make this safe.

### `identity.py`

_Who is who across systems: the matching that produces the master ID and the two counts._

Identity resolution: work out which records describe the same human, assign a
master ID, and count unique clients and unique client-program pairs.

Why this is a separate engine
-----------------------------
The duplicate check in the cleaning pipeline answers a narrow question: is this
the same record twice? It compares a fixed key and never guesses. That is right
for de-duplicating one export, and useless for linking a person across systems,
because the fields it compares are exactly the ones that change: a surname after
marriage, a first name recorded as a nickname, an address after a move.

This engine answers a different question: which records describe the same
person? That question cannot be answered by string similarity, because the hard
cases are not near misses. Robert and Bob share two letters. A maiden and a
married surname share none. So instead of comparing strings, this engine looks
for agreement across several independent pieces of evidence, and reports what it
found rather than deciding on its own.

The rule that keeps this safe
-----------------------------
Records are joined automatically only on evidence that cannot reasonably be a
coincidence. Everything else becomes a proposed link carrying the specific
reason it was proposed, for a person to confirm or reject. Confirmed and
rejected decisions are stored and replayed, so the work is done once.

Because some links stay unconfirmed, the client count is reported as a range:
the count if every proposal is accepted, and the count if every proposal is
rejected. A single number would imply a precision the data does not support.

### `table_detect.py`

_Finding the separate tables on one sheet, the header row, and what kind of table each is._

Table detection: find the separate, complete tables inside one spreadsheet or
sheet, so that two datasets sitting side by side (or stacked) are never merged
into one corrupted table.

The method is deterministic and explainable, with no guessing:

  1. Read the sheet into a grid of cleaned text values.
  2. Split the region by fully blank ROWS, then by fully blank COLUMNS, and
     recurse. A fully blank row or column is a separator, which is how people
     actually lay out multiple tables on one tab.
  3. Each remaining block is one table. Detect its header row, then describe it
     (range, size, columns, fill rate, empty columns, sensitive fields) and
     classify it as record-level or summary so a person can decide what to keep.

Nothing is altered or dropped. Detection only partitions the sheet, and the
caller chooses which tables to include.

### `setups.py`

_Named run set-ups, saved without client data and checked part by part against the current build before loading._

Saved set-ups: the work of configuring a run, kept so it need not be redone.

A set-up records what shaped a run and nothing else: the files by name and
the columns each had, the header rows, the column set-up, the tidy-up steps,
how columns were matched, the defaults per file, how program names were
grouped, what counted as a duplicate, and the settings. No client data is
written, ever. A set-up is loaded against whatever files are present now:
each part is checked against the current build and the current files, and
anything that no longer fits is reported by name rather than applied blindly
or silently dropped. The tool changes over time; a set-up that quietly stopped
working would be worse than none.

#### `stem(key)`

or fewer rows is still the same file: 'a.xlsx :: Sheet1 :: A1:I58' and
'a.xlsx :: Sheet1 :: A1:I70' both give 'a.xlsx :: Sheet1'.

Where a set-up's file lives.

The saved set-ups, with any that cannot be read marked as broken rather than hidden.

Read one saved set-up from disk.

#### `check_setup(d, S, app_version, known_op_types, known_roles, describe_op, default_schema=None)`
Check every part of a saved set-up against the current build and the files

#### `apply_setup(d, S, known_op_types, present_tables)`
Apply what fits. Parts the check flagged are skipped, so what is loaded is

### `sessions_store.py`

_Saving progress between sessions: decisions and set-up only, purged after seven days._

Autosave and resume.

What is saved, and what is deliberately not
------------------------------------------
A session file holds the decisions that took human time: the schema, the
staging steps, the column mapping, per-source defaults, the header row chosen
for each table, run settings, and every review decision. Losing those on a
nineteen thousand row batch would cost hours.

Uploaded files and the tables read from them are NOT saved. They stay in memory
and disappear when the server stops. This keeps the promise the rest of the tool
makes: client data is not written to disk unless an operator exports it. On
resume the operator points at the same source files again and the saved
decisions are replayed onto them.

One exception is named honestly rather than hidden. A correction typed during
review, for example a corrected borough, is part of a decision and is saved with
it. Those are single field values, not records, and a session file never
contains a whole row. If even that is unacceptable on a given machine, autosave
can be turned off and the tool behaves exactly as before.

Sessions older than seven days are deleted on startup and whenever a session is
saved.

### `launch.py`

_The double-click launcher: checks, installs once, picks a port, starts the server, opens the browser, stops when the window is gone._

Crosswalk launcher.

Started by double-clicking Crosswalk.vbs on Windows, Crosswalk.command on a
Mac, or Crosswalk.sh on Linux. It is written so that the person launching the
tool never needs a terminal and never has to read a stack trace.

It does five things, and explains itself in plain words if any of them fail:

  1. checks the Python it is running on is new enough
  2. installs what the tool needs, once, on the first run only
  3. picks a free port, so a second copy or another program does not collide
  4. starts the server and waits until it is actually answering
  5. opens the browser at the right address

Anything that goes wrong is shown in a message box and written to
launch-log.txt next to this file, so a problem can be reported without needing
to reproduce it.

#### class `_LogStream`
Somewhere for output to go when there is no console.

Started by double-clicking, the tool runs under pythonw, which gives it no
standard output at all: sys.stdout is None. Any library that reaches for it
then fails, and uvicorn does exactly that when it sets up its own logging.
Sending that output to the log file keeps those libraries working and keeps
anything they say where it can be read afterward.
- `__init__(self, path)`: Creates one, with the values given.
- `write(self, text)`: Write to the log file, standing in for a console that is not there.
- `flush(self)`: Nothing to flush; the log is written line by line.
- `isatty(self)`: Never a terminal, so no color codes.
- `fileno(self)`: There is no file descriptor when running without a console.

#### `_ensure_streams(path)`
Give the process an output stream when it was started without one.

#### `log(message)`
Write one line to the launch log, and to the screen when there is one.

#### `tell(title, message, is_error=True)`
Say something to a person who has no terminal open.

A native message box is used where one is available. Everything is written
to the log as well, so the words are recoverable afterward either way.

#### `check_python()`
Refuse to start on a Python too old to run the tool, saying which to install.

#### `missing_packages()`
The packages the tool needs that are not installed.

#### `install_requirements()`
Install what is missing, once. Later runs skip this entirely.

#### `free_port(preferred=8765)`
The usual port when it is free, otherwise any port that is.

#### `already_running(port)`
The version of the copy answering on this port, "unknown" for a copy too
old to say, or None when nothing is there.

#### `_pids_listening_on(port)`
Process ids listening on a local TCP port, from /proc on Linux.

#### `stop_whatever_holds(port)`
Stop the process listening on this port, whatever it is.

Used when an older copy of the tool is still running: opening that one
instead of this one silently hands the person the old version, which is
what happened when an old folder could not be deleted. The polite request
is tried first; an old copy ignores it, so the process is then found by
its port and ended.

#### `wait_until_ready(port, seconds=90)`
Wait until the server answers, for up to the seconds given.

#### `main()`
Check, install once, pick a port, start the server, open the browser, and stay until the window is gone.

## 8. The interface (`ui/app.js`)

A single page with no framework. `UI` holds the page's own state (which screen, filters, pending choices). `load(screen)` fetches that screen's payload and calls `render()`, which rebuilds the content from one `vScreen()` function per stage: `vCheck`, `vSources`, `vSchema`, `vPrepare`, `vMap`, `vPrograms`, `vRun`, `vReview`, `vQueue`, `vSummary`, `vProposals`, `vExport`, `vAudit`. One document-level click handler dispatches on `data-act` and `data-*` attributes. Grids keep their scroll position across a redraw. Every request shows a bar; when the server reports processing, the screen grays out behind one card. Help buttons read `ui/help.json`.

Choices that used to cost a round trip each are held locally and applied once: program grouping (`progLocal`, `progApply`), review group decisions (`pendingGroups`), duplicate decisions (`pendingDups`).

## 10. Keeping this current

Documentation is generated, not written, wherever it describes the code:

- `python tools/make_docs.py` rebuilds this file, the user guide and the cheat sheets.
- `python tools/take_screenshots.py` retakes the screenshots the guide and the deck use.
- `python tools/make_guide_docx.js` and `tools/make_deck.js` rebuild the Word guide and the PowerPoint deck from the same sources.
- `tests/test_docs.py` fails when the generated files no longer match the code, and when any public function or class lacks a docstring, which is what the reference is built from.

So the rule for a change is: change the code, add the docstring, run the generators, run the tests.
